# Packet Capture & Network Analysis Guide

A hands-on, educational guide to capturing, analyzing, and dissecting the network traffic generated between our Controller and Client using **Wireshark**, **tshark**, and **tcpdump**.

---

## 1. Network Capture Architecture

When our Controller (`core.controller`) and Client (`core.client`) communicate on port `4444`, they exchange TCP packets encrypted with Transport Layer Security (TLS).

```text
[ Client (Terminal 2) ]                          [ Controller (Terminal 1) ]
       │                                                      │
       ├────────────── 1. TCP 3-Way Handshake ───────────────┤
       │   SYN ──────────────────────────────────────────>   │
       │   <────────────────────────────────────────── SYN-ACK
       │   ACK ──────────────────────────────────────────>   │
       │                                                      │
       ├────────────── 2. TLS Handshake ─────────────────────┤
       │   Client Hello ─────────────────────────────────>   │
       │   <──────────────────────────────── Server Hello,   │
       │                                     Certificate,     │
       │                                     Key Exchange     │
       │   Finished ─────────────────────────────────────>   │
       │   <───────────────────────────────────── Finished   │
       │                                                      │
       ├────────────── 3. Encrypted Application Data ────────┤
       │   [Encrypted JSON: Auth Challenge] <─────────────   │
       │   [Encrypted JSON: Auth Response]  ─────────────>   │
       │   [Encrypted JSON: Status Telemetry] ───────────>   │
       │   [Encrypted JSON: Heartbeat Ack]  <─────────────   │
```

## 2. Capturing Traffic in Your Lab

### Option A: Arch Linux / WSL2 (CLI via `tcpdump` or `tshark`)

To capture traffic on the local loopback interface (`lo`):

```bash
# Capture using tcpdump into a .pcap file
sudo tcpdump -i lo port 4444 -w lab_session.pcap

# Or capture live with tshark (Wireshark CLI)
tshark -i lo -f "tcp port 4444" -Y "tls"
```

### Option B: Windows (Wireshark GUI)

1. Open **Wireshark**.
2. Select the **Adapter for loopback traffic capture** (installed via Npcap).
3. In the display filter bar at the top, enter:

   ```text
   tcp.port == 4444
   ```

4. Start capturing, then run the controller and client:

   ```bash
   python -m core.controller --port 4444
   python -m core.client --port 4444
   ```

## 3. Dissecting the Protocol Flow

### 3.1 The TCP 3-Way Handshake

Before encryption begins, the operating system kernel establishes a reliable stream:

- `SYN`: Client asks to connect (`Seq=0`).
- `SYN, ACK`: Controller acknowledges and responds (`Seq=0, Ack=1`).
- `ACK`: Client confirms connection established (`Ack=1`).

### 3.2 The TLS Handshake

Wireshark parses TLS protocol structures into readable trees:

| Packet Step | Protocol Message | What Defenders / Eavesdroppers See |
| :--- | :--- | :--- |
| **Client Hello** | `Handshake: Client Hello` | Supported TLS versions (e.g., TLS 1.3), cipher suites, supported elliptic curves, SNI (Server Name Indication). |
| **Server Hello** | `Handshake: Server Hello` | Selected cipher suite (e.g., `TLS_AES_256_GCM_SHA384`), server key share. |
| **Certificate** | `Handshake: Certificate` | The X.509 certificate generated by `crypto_utils.py`. The Common Name (`CN=localhost`), issuer, validity dates, and public key are sent. |
| **Finished** | `Handshake: Finished` | Authenticated handshake confirmation. All subsequent bytes are encrypted. |

### 3.3 Encrypted Application Data

Once the handshake finishes, all application records are classified as:

```text
TLSv1.3 Record Layer: Application Data Protocol: Hypertext Transfer Protocol / Raw Data
    [Encrypted Application Data: 198 bytes]
```

No IP eavesdropper can see:

- The JSON schema or command names
- The HMAC authentication response
- The client hostname, OS, or hardware telemetry

## 4. Comparing Plaintext vs. Encrypted Traffic

In educational labs, compare what is leaked if TLS is disabled versus enabled:

### Without TLS (Plaintext TCP)

If plain TCP were used, Wireshark's **Follow TCP Stream** reveals:

```json
{"type": "status_report", "client_id": "laptop-arch", "platform": {"os": "Linux", "arch": "x86_64", "kernel": "6.18.54"}}
```

> **Risk**: Any observer on the local network (or Wi-Fi) can view the machine's configuration, operating system, internal network identifiers, and pre-shared tokens.

### With TLS (Our Lab)

The same stream appears as high-entropy pseudo-random bytes. The payload contents, structure, and credentials remain confidential.

## 5. Behavioral Traffic Analysis (Defensive Perspective)

Even when traffic is fully encrypted, network security monitors (Zeek, Suricata, Snort) analyze **metadata** and **traffic patterns**:

### 1. Periodic Beaconing Detection

Our client sends a status report or heartbeat every $N$ seconds (default: 5s).

- **Signature**: Regular packet spikes of uniform size (e.g., ~200 bytes) at exact 5.0-second intervals.
- **Defensive Alert**: Highly regular periodicity with low jitter is a primary heuristic used by network defense tools to flag automated agents or beaconing C2 channels.
- **Hardening Principle**: In production administration agents, introducing **jitter** (e.g., $5s \pm 30\%$ random variation) prevents static interval detection.

### 2. Certificate Anomalies

- Self-signed certificates or certificates with localhost/test names trigger alerts in enterprise IDS sensors.
- Real enterprise agents use corporate Public Key Infrastructure (PKI) with pinned internal root CAs.

## 6. Educational TLS Decryption with `SSLKEYLOGFILE`

To inspect your own encrypted lab session inside Wireshark for educational verification:

1. **Export the TLS master secrets log file**:

   ```bash
   # On Linux / WSL2:
   export SSLKEYLOGFILE=~/sslkeys.log

   # On Windows (PowerShell):
   $env:SSLKEYLOGFILE = "$HOME\sslkeys.log"
   ```

2. Run `controller.py` and `client.py` in that terminal. Python's `ssl` module will write the session keys to `~/sslkeys.log`.
3. In Wireshark:
   - Go to **Edit** → **Preferences** → **Protocols** → **TLS**.
   - Set **(Pre)-Master-Secret log filename** to `~/sslkeys.log`.
4. Wireshark will now decrypt the TLS session in real time, revealing the inner decrypted JSON frames alongside the encrypted packets.

## 7. Essential Wireshark & Tshark Filters

```text
# Filter on our lab port
tcp.port == 4444

# Filter for TLS handshakes only
tls.handshake

# Filter for Client Hello packets
tls.handshake.type == 1

# Filter for Certificate exchange
tls.handshake.type == 11

# Find connection resets or abrupt terminations
tcp.flags.reset == 1
```

Using `tshark` CLI to display handshake details:

```bash
tshark -r lab_session.pcap -Y "tls.handshake" -T fields -e frame.time -e ip.src -e ip.dst -e tls.handshake.type
```
